# 평문을 한눈에 읽히는 모양으로

사용자(교사 등 비개발자)가 화면을 **훑어보고 바로 판단**할 수 있게 한다. 문장 속에 숨은 숫자·상태를 꺼내 모양으로 보여 준다.
이 규칙은 모든 프로젝트에 적용한다. 프로젝트에 디자인 기준 문서(예: `docs/design-standards.md`)·색 변수가 있으면 그 이름표를 우선 쓴다.

## 1. 무엇을 어떤 모양으로 (먼저 이 표로 고른다)

| 평문의 종류 | 바꿀 모양 | 예 |
|---|---|---|
| 숫자 하나 + 짧은 상태 | **뱃지(칩)** | "311명 중 268등" → `311명 중 268등` 뱃지 |
| 좋다/주의/나쁘다가 있는 상태 | **색 뱃지**(4가지 뜻 색) | "커트라인보다 1.2%p 뒤" → 빨간 뱃지 |
| 같은 종류의 숫자 여러 개 | **표** (만점 줄 + 값 줄) | "교과 64 + 출석 14 + 봉사 8 …" → 한 줄 표 |
| 값 / 만점 | **점수 칸** "값 / 만점", 만점 미달이면 테두리 강조 | 출석 14.0 / 16 |
| 행 × 열로 된 등급·성취도 | **히트맵**(칸 배경색) | 과목 × 학기 성취도 A~E |
| 전체 중 위치·비율 | **막대·게이지** | 상위 86% 위치, 커트라인 구간 |
| 시간에 따른 변화 | **작은 추세선·막대** | 학기별 평균 |
| "제목: 내용 · 내용" | **이름표 줄** (앞에 짧은 이름표) | `작년 우리 학교` │ 합격 180명 · 불합격 15명 |
| 놓치면 안 되는 경고·감점·미입력 | **경고 상자** 하나에 모으고 항목은 뱃지 | ⚠ 비교과 감점 8점: `출석 −2` `창체 −3` |
| 계산 과정 | **식 뱃지** | `기본 4` + `학년별 12` = `출석 16 / 16` |
| 순서가 있는 일 | **단계 표시** (번호·완료/진행 중) | 1단계 초기 설정 ✓ → 2단계 … |
| 긴 안내·근거 설명 | **접기** 또는 작은 보조 글 | "산출 근거 보기 ⌄" |

고르기 어려우면: 숫자를 비교해야 하면 표, 한 덩어리 상태면 뱃지, 많은 칸의 강약이면 히트맵, 설명이면 접기.

## 2. 지켜야 할 규칙

1. **색은 뜻 4가지만**: 좋음(초록)·주의(노랑)·나쁨(빨강)·안내(파랑/남색), 그 밖은 회색. 장식용 색을 늘리지 않는다. 프로젝트의 판정 색 변수가 있으면 그것을 쓴다.
2. **색만으로 뜻을 전하지 않는다**: 글자(예: "뒤", "미입력", "−2.0")나 기호를 함께 둔다. 색약·흑백 인쇄 대비.
3. **뱃지 하나에 생각 하나**. 뱃지 안 숫자는 굵게, 자릿수가 맞는 숫자 글꼴(`font-variant-numeric: tabular-nums`).
4. **모든 것을 뱃지로 만들지 않는다**. 한 줄에 뱃지 4~6개를 넘기면 표로 바꾼다. 핵심 숫자 하나는 크게, 나머지는 뱃지·보조 글.
5. **같은 숫자를 두 번 보여 주지 않는다**. 요약(위)과 상세(아래)가 겹치면 요약은 뱃지 한 줄, 숫자는 표 한 곳에만.
6. **원래 쓰는 말을 그대로**: 공식 시스템(예: 나이스)이 쓰는 칸 이름·순서를 따르면 사용자가 원본과 나란히 맞춰 볼 수 있다. 줄임말을 새로 만들지 않는다.
7. **경고는 한곳에**: 흩어진 "주의" 문장을 경고 상자 하나로 모은다. 경고가 없으면 상자도 없다.
8. **글자 크기 단계를 지킨다**: 보조 글은 본문보다 작게(최소 12px), 큰 글씨를 설명 문단에 쓰지 않는다.
9. **겹침 확인**: 막대 끝(0%·100%)의 글자, 좁은 칸의 긴 선택지는 겹치거나 잘리기 쉽다. 끝에서는 글자를 안쪽으로 맞추고, 겹치면 덜 중요한 글자를 숨기며, 긴 설명은 선택지 밖 안내 글로 뺀다.
10. **라이트·다크·인쇄 세 가지 모두**: 색 변수로 두 테마를 맞추고, 인쇄에서는 옅은 배경색 + 진한 글자로 고정한다(`print-color-adjust: exact`). 인쇄물은 A4 한 장에 맞는지 본다.

## 3. 만들고 나서 확인

- [ ] 화면을 3초 보고 핵심(판정·위치·점수·경고)을 말할 수 있는가
- [ ] 문장 속에 숨은 숫자·상태가 남아 있지 않은가
- [ ] 같은 숫자가 두 곳에 나오지 않는가
- [ ] 색 없이(흑백)도 뜻이 읽히는가
- [ ] 글자 겹침·잘림이 없는가(좁은 화면, 값이 끝(0·100)일 때 포함)
- [ ] 라이트·다크·인쇄를 실제로 찍어 보았는가
- [ ] 공식 원본과 칸 이름·순서가 같은가(맞춰 보는 화면이라면)

## 4. 부품 이름 (프레임워크가 있으면 이 이름으로 공통 부품을 만든다)

`InfoBadge(tone)` · `LabeledRow(label)` · `AlertBox(tone, title)` · `ScoreTile(value, max)` · `PositionBar(pct, band)` · `HeatCell(level)` · `FormulaChips` · `StepList` · `Fold(summary)`.
React 등으로 옮길 때는 화면마다 따로 만들지 말고 이 부품을 한 번 만들어 함께 쓴다.

## 5. 하지 말 것

- 문장을 그대로 두고 색만 칠하기
- 뱃지에 긴 문장 넣기(잘린다)
- 장식용 이모지·색 남발(뜻 없는 색은 사용자를 헷갈리게 한다)
- 경고를 빨간 글씨 문장으로 여러 줄 늘어놓기
- 선택 상자(select)의 선택지에 긴 설명 넣기 → 짧은 이름 + 아래 안내 글
