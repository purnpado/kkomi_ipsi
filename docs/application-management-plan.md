# 원서 관리 화면 구현 계획 (다음 버전, 2026-11-13 사용자와 합의)

> 구현 전 계획서다. 윈도우 후보 점검·릴리즈 뒤 다음 버전에서 구현한다.
> 계산식·판정 기준·교환 파일 형식은 바꾸지 않는다. 바뀌는 것은 원서 입력·결과 처리 방법과 취합 병합 규칙이다.

## 1. 배경 (학교 운영 방식)

- 학년부장이 기초 작업(나이스 자료 올리기)을 하고 프로그램과 배포자료를 담임에게 전달한다. 담임은 그것으로 상담한다.
- 대부분의 학생은 **후기 일반고**에 지원하고, 마이스터고·특성화고·기타(자사고·외고 등) 지원자는 적다. 일반고 불합격자도 적다.
- 전기고 원서 접수는 대부분 나이스에서 하고, 담임이 학년부장에게 **구두로** 알린다.
- 합격·배정 발표는 나이스에서 확인한다. **나이스는 합격·배정 결과를 파일로 주지 않는다**(파일 올리기 기능은 만들지 않음).
- 학생 수가 많은 학교는 담임이 반별로 입력해 취합자료로 내는 편이 낫고, 적은 학교는 학년부장이 직접 처리하는 편이 낫다. **두 방식을 모두 지원한다.**

## 2. 권한

| 역할 | 원서 관리 범위 |
|---|---|
| 학년부장 | 전교생 |
| 담임 | 우리 반 |
| 진로부장 | 조회만 |

- "원서는 학년부장만 관리" 같은 설정은 두지 않는다(사용자 결정).
- 입시 결과를 확정한 학년도는 지금처럼 수정·일괄 처리를 막는다.

## 3. 화면: 원서·결과 → "원서 관리" (새 화면, `views/applications/` 예정)

학생 한 줄 = 반·번호·이름(전입 뱃지)·올해 원서(학교·전형·학과·상태)·결과. 반 고르기(학년부장)·이름 찾기·상태별 거르기(원서 없음/지원 예정/결과 없음 등).

### 단계별 기능

1. **[일반고 일괄 지원]** (기초 작업)
   - 올해 원서가 하나도 없는 학생에게 "후기 일반고 · 지원 예정" 원서를 만든다. 이미 있는 원서는 건드리지 않는다.
   - 실행 전 "N명에게 만듭니다" 미리보기.
2. **전기고 원서 빠른 입력** (담임이 구두로 알려 준 학생)
   - 이름 입력 → 학교·전형·학과(1~5지망) 선택 → 저장, 키보드만으로 다음 학생으로.
   - 전기고 원서를 넣어도 일반고 원서는 남긴다(전기고 불합격이면 일반고로 가기 때문).
3. **학교별 결과 입력** (전기고 발표 뒤)
   - 학교·전형을 고르면 그 학교 지원자만 목록. 나이스 발표를 보며 **합격자만 체크** → [나머지 불합격]. 1차·2차 구분, 배정 학과도 그 자리에서.
   - 전기고 **합격자의 일반고 원서는 자동으로 "미지원"** 처리(울산: 전기고 합격자는 후기고 지원 불가). 확인 창에 인원 표시.
4. **[일반고 일괄 합격]** (후기 발표 뒤)
   - 결과가 없는 일반고 원서를 모두 "합격". 이어서 **불합격자만 체크**해 바꾼다. 추가모집 합격도 이 화면에서 입력.
5. **배정학교**: 원서대장처럼 칸에 바로 입력.

### 안전장치

- 모든 일괄 처리: 실행 전 인원 미리보기, 실행 뒤 **[방금 일괄 처리 되돌리기]**(일괄로 만든·바꾼 원서에 작업 묶음 표시를 남겨 그 묶음만 되돌림).
- 결과 확정 학년도는 거부(백엔드에서 막음).
- 원서 점수는 지금처럼 저장 시점의 산출값(일반고는 내신, 전기고는 1차 산출 점수)을 넣어 분석·관내 공유가 그대로 이어지게 한다.

## 4. 취합 병합 규칙 변경 (필수)

- **지금 동작(2026-11-13 확인)**: `DBManager.ApplyPatchChange`가 취합자료의 원서를 `SaveApplication`으로 **수정 시각 비교 없이 덮어쓴다**. 담임과 학년부장이 둘 다 원서를 고치면 오래된 취합자료가 학년부장의 최근 일괄 처리를 덮을 수 있다.
- **바꿀 동작**: 같은 학생·같은 학교·전형 원서는 `updated_at`이 **더 최근인 쪽을 남긴다**. 학년부장 쪽이 더 최근이면 건너뛴다.
- 병합 미리보기(`InspectTeacherPatch`·`patchMergeView.js`)에 "학년부장 쪽이 더 최근이라 건너뜀 N건"을 표시한다.
- 테스트: 학년부장 일괄 합격 뒤 그 전에 만든 담임 취합자료를 병합해도 결과가 유지되는지, 담임이 더 최근에 고친 원서는 반영되는지.

## 5. 백엔드 (예정)

- App(학년부장 전교, 담임 본인 반, 진로부장 거부, 확정 학년도 거부):
  - `BulkCreateGeneralApplications(year, classNum)` — 미리보기용 `PreviewBulk...` 함께
  - `BulkSetSchoolResults(year, school, track, acceptedKeys, firstStage)` — 전기고 합격자 일반고 "미지원" 처리 포함
  - `BulkAcceptGeneral(year, classNum)`
  - `UndoBulkOperation(batchID)`
- 원서 기록에 일괄 작업 묶음 id(되돌리기용) 칸 추가 — DB 마이그레이션은 기존 자료 100% 보존(AGENTS.md 원칙 8).
- 파일당 500줄 이하, 화면 간 직접 호출 금지(이벤트·`navigate`), 캡처 도구(`tools/capture`)에 새 화면 추가.

## 6. 연결

- 학년부장 대시보드 진행표 "원서 취합"·"결과 입력" 단계 → 원서 관리 화면으로.
- 담임 대시보드 "원서 미입력" → 원서 관리(우리 반, 원서 없음 거르기).
- 사용 설명서(`modals/guide/`)에 원서 관리 단계 추가.
