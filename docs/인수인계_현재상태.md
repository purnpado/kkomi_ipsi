# 꼬미입시(PHGC) 현재 상태 및 이어서 작업하기

이 문서는 다른 컴퓨터나 다른 작업자가 저장소를 이어받을 때 먼저 읽는 인수인계 문서입니다.

## 현재 기준

- 표시 명칭: **꼬미입시**
- 기술 식별자: `PHGC` (저장소·파일 형식·배포자료 확장자 호환용)
- 최신 안정 릴리즈: `v1.6.2`
- 공식 저장소: `https://github.com/purnpado/PHGC`
- Gitea 백업: `https://gitea.gguk.link/purnpadosori/PHGC-OFFLINE`
- 공식 배포: GitHub Releases의 `PHGC.exe`

## 로컬 개발 준비

1. Go, Node.js, Wails CLI, WebView2가 설치된 Windows 환경을 준비합니다.
2. 저장소를 복제하고 프로젝트 루트에서 `go test ./...`를 실행합니다.
3. 프론트엔드 확인은 `Set-Location frontend; npm install; npm run build`로 합니다.
4. 데스크톱 개발 실행은 루트에서 `wails dev`, 배포 빌드는 `wails build -trimpath -ldflags "-s -w"`입니다.

## 배포 전 확인

- `git status -sb`에서 의도하지 않은 `data/`, DB, 나이스 원본, 개인 파일이 없어야 합니다.
- `go test ./...`, `npm run build`가 통과해야 합니다.
- 실행 파일은 `build/bin/PHGC.exe`이며, 릴리즈 에셋 이름은 호환성을 위해 `PHGC.exe`로 유지합니다.
- 버전을 올릴 때 `server-data/version.json`, `sync.go`, 릴리즈 노트를 함께 갱신합니다.
- `publish.ps1 -Version "x.y.z" -Notes "한국어 노트"`는 빌드, 커밋, 태그, GitHub·Gitea 푸시와 릴리즈 에셋 업로드를 수행합니다.

## 데이터·보안 원칙

- 학생 개인정보와 상담 자료는 로컬 `data` 폴더에만 저장합니다.
- DB와 `.phgcpkg`, `.phgcpatch`, `.phgcreset`, `.phgcdata`는 사용자가 설정한 공용 데이터 암호 기반 AES-256-GCM으로 보호합니다.
- DPAPI, 학생 개인정보 자동 수집, 원본 나이스 파일의 중앙 전송은 사용하지 않습니다.
- 고교 커트라인 중앙 제출 자료는 중학교명·입학년도·고교명·학과/전체·전형·점수 등 최소 항목만 포함합니다.

## 사용자 업무 흐름

학년부장이 학교 기초 설정과 나이스 자료 처리를 완료한 뒤 담임별 `.phgcpkg`를 만들고, 담임은 새 폴더에서 배포자료를 적용합니다. 담임의 상담·지원·합격 기록은 `.phgcpatch`로 학년부장에게 전달되며, 학년부장이 검토·병합 후 최신 자료를 재배포합니다.

## 변경 시 주의

- `PHGC` 형식 문자열과 확장자를 임의로 변경하면 기존 배포자료와 자동 업데이트가 깨질 수 있습니다.
- 고교 산출식은 공식 요강과 표본 학생 계산값을 대조한 뒤 수정합니다.
- 운영 데이터와 개인 파일은 커밋하지 않습니다.
