# 꼬미입시 화면 개편 설계안 (v1.7 목표, 초안 2026-11-12)

> 이 문서는 구현 전 확정용 설계안이다. 계산·저장(백엔드)은 바꾸지 않고 화면 구조만 바꾼다.

## 1. 지금 화면의 문제

- 학년부장 대시보드 한 화면에 성격이 다른 버튼이 모두 모여 있다: 나이스 올리기·커트라인·계정·취합 병합·인수인계·고입 연도 변경·학급 수 변경·새 학년 시작·전체 초기화·매트릭스·지원현황·원서대장·입시 분석·관내 공유.
- 담임 화면은 학급 카드 → 명렬표 → 학생 상담 창으로 들어가는 구조라, "지금 무엇을 해야 하는지"가 첫 화면에 없다.
- 주요 기능 대부분이 창(모달)이어서, 창 위에 창이 겹치고 뒤로 가기가 없다.
- 진로부장은 담임 화면을 빌려 쓰고 있어, 조회 전용 역할에 맞는 첫 화면이 없다.

## 2. 공통 틀

```
┌────────────────────────────────────────────────────────────┐
│ 꼬미입시 · 가람중학교 · 2027 고입(현 중3)   🔍학생 검색  🔒잠금  ⏻ │  ← 위쪽 막대
├──────────┬─────────────────────────────────────────────────┤
│ 대시보드   │                                                 │
│ 학생·성적  │            선택한 메뉴의 화면(한 화면 단위)            │
│ 상담       │                                                 │
│ 원서·결과  │                                                 │
│ 입시 분석  │                                                 │
│ 기준 자료  │                                                 │
│ 자료 주고받기│                                                │
│ 설정       │                                                 │
│ ─────    │                                                 │
│ ❓ 도움말   │                                                 │
│ 💬 질문·피드백│                                               │
└──────────┴─────────────────────────────────────────────────┘
```

- 왼쪽 메뉴는 역할마다 다르게 보인다(권한 없는 메뉴는 아예 감춘다).
- 자주 쓰는 기능(명렬표, 상담, 원서, 분석, 커트라인)은 창이 아니라 화면으로 연다. 확인·입력이 짧은 것만 창으로 둔다.
- 위쪽 학생 검색으로 어느 화면에서든 바로 상담 화면을 연다.
- 화면 이동은 지금처럼 `core/navigation.js`의 이벤트로만 한다(새 화면은 `main.js` 라우팅 표에 등록).

## 3. 역할별 대시보드

### 학년부장 — "올해 할 일" 중심

| 영역 | 내용 |
|---|---|
| 학년도 진행표 | 초기 설정 → 나이스 올리기(교과·출결·봉사) → 담임 배포 → 담임 취합 → 원서 접수 → 결과 입력 → 결과 확정 → 인수인계·관내 공유. 단계별 완료/남음 표시, 누르면 해당 화면으로 |
| 현황 카드 | 학생 수·자료 올림 상태, 반별 취합 제출 여부, 원서 현황(지원·합격·미입력), 마감까지 남은 날 |
| 주의 알림 | 고입 연도 안내 띠, 공식 경쟁률 미입력, 결과 확정 전 남은 미입력 원서 |
| 바로가기 | 신호등 매트릭스, 우리 학교 지원현황, 원서대장, 입시 분석 |

### 담임 — "우리 반" 중심

| 영역 | 내용 |
|---|---|
| 상담이 필요한 학생 | 희망 학교 판정이 "어려움"·"판단 근거 부족"인 학생, 상담 기록이 없는 학생 |
| 반 판정 분포 | 전기고·후기고 판정별 인원(누르면 해당 학생 목록) |
| 원서 진행 | 학생별 원서 입력·결과 입력 상태 |
| 할 일 | 비교과(출결·봉사·가산점) 확인, 취합자료 제출 여부·마지막 제출 시각 |
| 바로가기 | 명렬표, 반 지원현황, 매트릭스 |

### 진로부장 — 조회 전용

| 영역 | 내용 |
|---|---|
| 전교 판정 분포 | 학교·전형별 지원 희망 인원과 판정 분포 |
| 바로가기 | 입시 분석(추세·지망 전략), 신호등 매트릭스, 학생 검색(상담 화면 조회) |

## 5. 진행 단계

1. **설계 확정**: 이 문서와 화면 그림(클릭해 볼 수 있는 모형)을 보고 메뉴·대시보드 구성을 확정한다.
2. **공통 틀**: 위쪽 막대·왼쪽 메뉴·화면 전환 틀을 만들고, 기존 화면을 그대로 메뉴 안에 넣는다. 기능 변화 없음 → 자동 점검 도구(`tools/autopilot`)로 기존 흐름 확인.
3. **창 → 화면 전환**: 명렬표·상담·원서·분석·커트라인을 화면 단위로 옮긴다.
4. **역할별 대시보드**: 학년도 진행표·현황 카드·상담 필요 학생 목록을 새로 만든다. 필요한 집계는 기존 API를 우선 쓰고, 모자라면 조회 전용 API만 더한다.
5. **마무리**: 인쇄(상담표·원서대장·매트릭스) 확인, 화면 크기(노트북 1366×768) 확인, 도움말 갱신, 윈도우에서 실제 data 복제본으로 확인 후 릴리즈.

## 6. 바꾸지 않는 것

- 산출식·판정 기준·저장 형식·교환 파일 형식, 권한 규칙(진로부장 조회 전용, 담임 본인 학급만 수정).
- 파일당 500줄 이하, 화면 간 직접 호출 금지(이벤트로 연결).
