# 취합 병합 규칙 (학년부장 최종본)

2026-11-20 사용자 결정으로 만들었다. **학년부장 PC가 최종본**이고, 담임 취합 파일은 "이렇게 바꿔 달라는 요청"으로 다룬다. 학년부장 PC의 원서는 학년부장이 직접 고르지 않으면 지워지거나 덮이지 않는다. 병합한 뒤 학년부장이 배포자료를 다시 만들면 담임 PC도 그 최종본으로 맞춰진다.

## 기준 시각

| 이름 | 어디에 | 누구 시계 | 쓰임 |
|---|---|---|---|
| 배포 시각 `distributed_at` | 배포 사본의 학급 DB `class_meta` | 학년부장 PC | 학년부장 원서가 배포 뒤 바뀌었는지 |
| 받은 시각 `received_at` | 담임 PC 학급 DB `class_meta`(그 배포자료로 처음 로그인할 때 `MigrateExistingClassDBs`가 적음) | 담임 PC | 담임 원서·지운 기록이 배포 뒤 생겼는지(PC 시계가 달라도 같은 시계끼리 비교) |
| 제출 시각 `patch_exported_at` | 담임 PC 학급 DB | 담임 PC | 반 전체 취합 파일을 낸 시각(`SaveCurrentClassPatch`만 적음) |

취합 파일(`model.PatchFile`)에는 `formatVersion: 2`, `baseDistributedAt`, `baseReceivedAt`, 학생마다 `deletedApplications`(배포 뒤 지웠거나 학교·전형을 바꾼 원서의 옛 이름표)가 실린다. 예전 버전 프로그램은 이 항목을 모르고 넘어간다.

## 지운 원서 기록·병합 표시 (학급 DB)

- `application_deletions`: 원서가 지워지거나 이름표(학년도·구분·학교·전형)가 바뀌면 **DB 트리거**가 옛 이름표와 시각만 적는다(점수·상태 없음). 같은 이름표 원서가 다시 생기면 지운다. 화면·일괄 처리·되돌리기 어디서 바뀌어도 같다. 코드 `internal/database/application_deletion_repo.go`.
- `application_merge_marks`: 학년부장 PC에서 취합 병합으로 쓴 원서와 그 시각. 같은 시각이면 "학년부장이 직접 고친 원서"로 보지 않는다(같은 배포본으로 두 번째 제출할 때 충돌로 오판하지 않게).
- 원서 입력 창에서 이미 있는 원서의 학교·전형을 바꾸면 새 원서를 더하지 않고 제자리에서 고친다(`application_edit.go`). 이미 같은 학교·전형 원서가 있으면 저장을 막는다.

## 분류와 기본 처리 (`internal/database/application_patch_plan.go`)

| 분류 | 뜻 | 상세 검토 기본 | 일괄 병합 | 고를 수 있는 것 |
|---|---|---|---|---|
| `new` | 담임이 새로 넣은 원서 | 반영 | 반영 | 반영하지 않기 |
| `update` | 담임만 고친 원서 | 반영 | 반영 | 반영하지 않기 |
| `conflict_edit` | 학년부장도 배포 뒤 고침 | 학년부장 것 유지 | 유지 | 담임 것으로 바꾸기 |
| `gh_deleted` | 학년부장이 배포 뒤 지웠는데 담임은 고침 | 유지(지운 채로) | 유지 | 담임 것으로 바꾸기 |
| `gh_missing` | 학년부장 PC에 없고 지운 기록도 없음(예전 버전에서 지움, PC 시계 차이) | 유지 | 유지 | 담임 것으로 바꾸기 |
| `teacher_deleted` | 담임이 지움(학년부장은 손대지 않음) | 지우기 | 유지 | 남기기 |
| `conflict_deleted` | 담임이 지웠지만 학년부장이 배포 뒤 고침 | 유지 | 유지 | 지우기 |
| `rename` | 담임이 학교·전형을 바꿈(옛 이름표 기록과 새 원서가 3초 안) | 옛 원서를 새 원서로 바꾸기 | 유지 | 학년부장 것 유지 / 둘 다 남기기 |
| `rename_conflict` | 위와 같은데 학년부장이 옛 원서를 배포 뒤 고침 | 유지 | 유지 | 바꾸기 / 둘 다 남기기 |
| `suspect` | 예전 버전 파일: 같은 학년도·구분에 담임 새 원서와 학년부장 남는 원서 | 둘 다 남기기 | 유지 | 바꾸기 / 학년부장 것 유지 |

- 조용히 건너뜀: 학년부장만 배포 뒤 고친 원서(담임은 그대로), 학년부장이 배포 뒤 지운 원서(담임은 그대로), 확정된 학년도 원서(병합 전체가 실패하지 않음).
- 담임 파일에 없는 학년부장 원서는 그대로 두고 개수만 보인다.
- 반영할 때는 새 원서를 먼저 쓰고 옛 원서를 나중에 지운다.
- 배포 시각이 없는 파일(예전 버전, 또는 업데이트 전에 받은 배포본)은 고친 시각·지운 시각끼리 비교한다. 예전 버전 파일은 학년부장 원서를 지우지 않는다.
- 일괄 병합은 학년부장이 골라야 하는 원서를 모두 그대로 두고 반별 수를 알린다(`model.PatchBatchResult`).

## 배포자료 다시 가져오기 (담임 PC)

- 원서는 새 배포자료(학년부장 최종본)를 그대로 쓴다. 담임 PC 원서로 덮지 않는다(`internal/exchange/preserved.go`).
- 받은 시각·제출 시각 가운데 늦은 때 뒤에 고치거나 지운 원서가 있으면 아무것도 바꾸지 않고 `PendingConfirm`을 돌려준다. 화면이 "먼저 취합자료를 내세요"라고 묻고, 그래도 진행하면 `ImportDistributionPackageConfirmed`로 가져온다(그 원서는 `data/backup_before_pkg_import`에만 남음). 코드 `preserved_unsubmitted.go`.
- 상담 일지·관심학교·직접 입력한 출결/봉사/가산점은 지금처럼 보존한다.
