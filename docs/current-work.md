## 완료된 구현

- 후기 일반고 상담 화면: 점수와 석차백분율 판정을 구분하고 산출 근거·가산점 미입력 범위·관내 합격선 자료 유무를 표시한다. 화면과 인쇄물 가독성도 개선했다(v1.7.01 기존 내용).
- 입시 분석: 우리 학교 원서 기록에서 학교·학과·전형별 통계를 집계하고, 학교 전체와 해당 전형 자료가 없는 경우를 구분한다. 학과 공란은 학교·전형 전체를 뜻한다. 관내 공유 통계도 전형을 구분한다. 관련: `internal/database/analysis_ours.go`, `shared_stats.go`, `frontend/src/modals/analysis/analysisFilters.js`.
- 특성화고 전형 표시를 `취업희망자 특별전형`으로 통일하고 기존 `취업희망자`, `취업자 특별전형` 등의 저장값을 읽는다. 마이스터고 `특별전형`은 별도다. 2027학년도 특성화고 7개교 요강의 전형 구분을 확인했다. 원본 PDF는 로컬 `/Volumes/Transcend/입시요강 모음`에 있으나 다른 컴퓨터에는 없을 수 있다.
- 타시도·기타 고교는 지원 화면에서 학교명을 직접 입력하고 지원 기록에 저장한다. 기존 `타시도 고등학교` 기록을 열어 학교명을 입력하면 해당 기록의 ID와 메모를 보존한다. 메모에서 이름을 임의로 추출하지 않는다. 동일 학생의 다른 지원 기록을 덮어쓰지 않도록 중복을 거부한다. 원서대장도 저장된 학교명을 사용한다.
- 원서대장 타시도 학교명: 2026-11-18 격리된 가상 학생 환경에서 기존 원서 수정·저장 후 화면과 인쇄 미리보기, 내려받은 엑셀 파일에 실제 학교명이 나타나는 것을 확인했다.
- 후기 일반고 배정학교 입력란은 원서대장과 지원현황에서 제거한다(사용자 결정). 기존 저장 값은 삭제하지 않는다.
- 취합 원서 병합은 같은 학생·학년도·전형·학교에 대해 원본 시각이 엄격히 더 최근일 때만 덮어쓰며, 시각을 비교할 수 없거나 같은 시각이면 기존 값을 유지한다. 상세 미리보기에는 건너뛰는 최대 건수를 표시한다. 학교명 자체가 변경된 원서는 같은 키로 식별할 수 없으므로 별도 식별·충돌 처리 개선이 필요하다. 시스템 시계가 정확하지 않으면 시각 비교가 부정확할 수 있다.
- 자동 업데이트는 Windows에서 릴리즈 실행 파일과 `SHA256SUMS.txt`를 받아 확인 후 교체한다. 같은 버전끼리는 새 버전으로 판단하지 않는다.
- macOS `.app`은 앱과 같은 폴더의 `data`를 사용한다. 예전 앱 내부 `Contents/MacOS/data`는 앱 바깥에 데이터가 없을 때 복사하며 원본을 보존한다. 앱을 통째로 교체하기 전에는 기존 데이터부터 별도로 백업한다. 새 앱을 다른 폴더에 만들면 이전 앱 내부 데이터는 자동으로 발견되지 않는다.

## 미완료·다음 작업

1. **추가 화면 검증**: 타시도 학교명 저장·원서대장·엑셀·인쇄 미리보기는 가상 학생으로 확인했다. 기존 메모 보존, 다른 학교 기록 중복, 확정 학년도 잠금은 자동 테스트 외에 실제 화면과 Windows에서도 확인한다.
2. **Windows 실기기 검증**: 후보 실행 파일로 실제 학교 데이터의 별도 복제본에서 로그인, 지원 기록 수정, 입시 분석, 인쇄 및 이전 버전에서 자동 업데이트를 확인한다. 원본 데이터는 건드리지 않는다. SmartScreen·백신 반응도 확인한다.
3. **원서 관리 화면 및 취합 병합**: `docs/application-management-plan.md`의 일괄 지원·결과·되돌리기 화면은 미구현 계획이다. 취합 병합은 동일 키의 수정 시각 비교만 구현했으며, 학교명 변경 등 키가 달라지는 충돌 처리와 Windows 실기기 검증은 남았다.
4. **학교별 점수 산출 검증**: `docs/admission-score-audit-plan.md`의 공식 예제·실제 원자료 대조와 회귀 검증을 이어간다. 전형명 대조가 산출식 전체 검증을 뜻하지 않는다.
5. **동일 버전 재배포 주의**: 이번 사용자의 명시적 요청은 v1.7.01 재배포다. 이미 v1.7.01을 설치한 사용자는 버전 비교상 갱신 안내를 받지 못한다. 해당 사용자에게는 새 파일을 직접 교체하도록 안내하거나 후속 버전을 올려야 한다. 교체 전 GitHub 다운로드 2회는 사용자의 테스트였다고 확인했다.

## 테스트와 빌드

- Go 전체: `go test ./...`
- 분석 필터: `node --test frontend/src/modals/analysis/analysisFilters.test.js`
- 프런트엔드: `cd frontend && npm run build`
- Windows 배포: `wails3 build GOOS=windows` (macOS Intel에서 `ARCH=amd64` 명시). zip은 Python `zipfile`로 한글 파일명을 보존하고 `SHA256SUMS.txt`를 함께 게시한다.
- macOS 검증용 앱 빌드와 Windows 릴리즈는 구분한다. macOS 앱은 정식 배포 대상이 아니다.
- 릴리즈 상태 및 실제 테스트 결과는 공개 릴리즈와 작업 결과를 확인한다. 이 문서만으로 GUI·Windows 테스트 완료를 추정하지 않는다.
