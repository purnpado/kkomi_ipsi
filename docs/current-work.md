"방금 넣은 원서" 목록에서 새로 만든 원서는 [삭제]. 일반고 원서는 건드리지 않는다. 저장 뒤 자료는 다시 읽되 화면은 다시 그리지 않아 다음 학생 입력이 지워지지 않는다. 가상 자료로 키보드 입력·삭제·원서대장·원서 입력 창을 캡처해 확인했다. ④ 후기 일반고 동점자는 모두 합격 처리(사용자 확인) → 판정은 이미 "합격선과 같으면 합격"이라 코드 변경 없음, 감사 계획서 9.3절에 기록.

## 4. 최근 사용자 결정 (다시 묻지 않는다)

- **React·Radix 전환 순서와 방식**: 입시가 끝난 뒤 전환을 먼저 하고, 새 입시요강은 그 뒤에 반영한다. 브랜치를 따로 만들지 않고 main에서 하며, 전환 중에는 릴리즈하지 않는다(급한 오류는 마지막 릴리즈 태그에서 임시 갈래로). 학교명 저장 이름표는 바꾸지 않고(보일 때만 정식 이름이면 충분), 전환 때 학교명 표시 부품 하나로 모은다(2026-11-21).
- **커트라인 화면 버튼**: [전체연도 일괄 저장]·예전 형식 [자료 내보내기]·[타교자료 병합]은 뺀다(관내 공유는 [관내 공유 결과]). 모집정원은 매년 요강 반영 때 프로그램에 넣어 미리 채운다(지원자 수만 입력). 학교 카드는 처음에 모두 접는다(2026-11-20).
- **이중지원 금지**: 원서는 접수 뒤 반려가 없다. "포기"는 합격 뒤 등록 포기(미진학과 다름). 합격·최종 진학·포기 원서가 있는 학생은 그해 새 원서를 낼 수 없다(2026-11-20). **지원 시기 규칙은 2027 울산 입학전형 기본 계획 "4. 이중 지원 금지"대로**(전기 2개교 금지와 예외, 울산·타시도 같은 시기 금지, 자사고·외고·고운고 + 일반고 허용, 2026-11-21). "자사고·외고"와 "기타"는 "기타 울산 고교" 하나로. 관내 공유는 2027 고입부터만 보낸다.
- **학교명은 화면·인쇄·엑셀에 정식 이름(○○고등학교)**으로 보이고, 저장 이름표는 바꾸지 않는다. 매트릭스도 정식 이름 두 줄(2026-11-20).
- **나이스 원서 대조표는 원서 입력 창에서만**(상담 화면에서는 뺌). 원서 전체는 나이스 원서 입력 일람표에서 본다. 전기고 빠른 입력 탭에는 넣지 않음(써 본 뒤 결정, 2026-11-20).
- **상담 화면은 한 페이지 유지 + 학교별 판정 한 줄 요약(누르면 펼침) + 위쪽 바로가기**. 넓은 화면에서 위쪽 칸을 나란히 두는 것은 써 본 뒤 결정(2026-11-20).
- **취합 병합은 학년부장 PC가 최종본**: 학년부장이 배포 뒤 고치거나 지운 원서는 담임 파일이 저절로 덮거나 되살리지 못한다. 상세 검토에서 담임이 지운 원서는 기본 "지우기", 학교·전형을 바꾼 원서는 기본 "바꾸기"(학년부장이 그 원서를 손대지 않았을 때). 일괄 병합은 지우기·바꾸기·충돌 원서를 학년부장 것 그대로 두고 알린다. 담임 PC 배포자료 재가져오기는 원서를 학년부장 최종본으로 맞추고, 아직 내지 않은 원서는 경고 뒤 진행하면 백업에만 남긴다(2026-11-20).

- 나이스 원서 대조표는 **마이스터고·특성화고·후기 일반고 모두**(2026-11-21 바꿈. 예전 결정 "특성화고만"은 오해였음: 세 전형 모두 나이스 원서등록 메뉴가 성적·출결·봉사를 나이스 자료로 불러와 요강 산출식으로 계산하고, 리더십·창체·행동특성 가산점은 담임이 학업성적관리위원회 명단을 보고 나이스에서 직접 체크한다. 대조표의 가산점 줄은 상담 화면에서 체크한 값을 보여 준다). 나이스 파일에는 마감일이 없으므로 "마감일 기준 출결" 경고를 띄우지 않는다(2026-11-20).
- 리더십은 **학기별 체크**(1-2·2-1·2-2·3-1, 감사 계획서 3.2절 설계, 2026-11-20).
- 후기 일반고 **동점자는 모두 합격**: 판정은 합격선과 같은 점수를 합격으로 본다(2026-11-20).
- **추가모집**: 원서에 표시하고 원서대장 비고 "[추가모집]"(후기 일반고 다음 줄). **합격선 통계에는 그대로 넣는다**(미달이라 열린 것이므로). 관내 공유·인수인계에도 싣는다. **후기 일반고 불합격 학생**의 새 전기고 원서만 미리 체크하고 해제할 수 있다(해제하면 안내도 숨김). 일반고 합격 학생은 체크하지 않는다(2026-11-20).
- 일반고 **일괄 지원은 후기 일반고에만** 적용한다. 전기고는 빠른 입력으로 넣는다(2026-11-20).
- 원서대장 점수 칸: 입시 통계 제외 학생·타시도·별도전형 학교는 "별도전형"(진로부장도 같게, 사유 없음, 2026-11-19).
- 타시도 고교는 유형(자사고·외고·특목고·마이스터고·특성화고·일반고)과 상관없이 하나의 "타시도 고교" 구분(2026-11-19).
- 전입생 봉사 환산: 타 시·도 전입만 환산, 울산 관내 전입은 환산하지 않음. 전입일은 나이스 파일에 없어 손으로 넣는다(2026-11-19).
- 후기 일반고 배정학교는 입력하지 않는다(2026-11-18).

## 5. 주의

- **동일 버전 재배포**: 예전 v1.7.01 재배포처럼 같은 버전 번호로 다시 올리면, 이미 설치한 사용자는 갱신 안내를 받지 못한다. 고친 것이 있으면 버전을 올린다.
- 맥 앱 `bin/꼬미입시.app`은 시험용이다. 릴리즈에 올리지 않고, 다시 빌드하기 전에 앱 안팎의 `data`를 먼저 백업한다.
- 학생 DB·`data/`·나이스 원본·암호화 교환 파일은 커밋하지 않는다. 의도한 파일만 `git add` 한다.

## 테스트와 빌드

- Go 전체: `go test ./...` (변경 뒤 항상)
- 화면 단위 테스트 전체: `cd frontend && node --test $(find src -name "*.test.js")` (2026-11-20 기준 15개)
- 프런트엔드 빌드: `cd frontend && npm run build`
- 바인딩 다시 만들기(Go 구조체·App 메서드를 바꿨을 때): `wails3 generate bindings -clean=true -i`
- 화면 확인: `zsh tools/capture/run.sh` (가상 자료 `test-data/시뮬레이션/열람용/가람중학교/data` 사본으로 서버 모드 실행·캡처). 직접 조작이 필요하면 `go build -tags server -o test-data/capture/server/kkomi .` 뒤 가상 자료를 복사해 `WAILS_SERVER_PORT=34851`로 띄우고 `tools/capture/lib/session.js`(login·clickMenu 등)를 쓰는 임시 puppeteer 스크립트를 스크래치 폴더에 만든다. **프런트를 고친 뒤에는 서버 실행 파일도 다시 빌드해야 새 화면이 나온다.** 가상 자료의 2027 학년도가 확정돼 있으면 사본에서만 `ReopenAdmissionYear`를 먼저 부른다.
- 파일 줄 수: 모든 `.go`·`.js`·`.css`는 500줄 이하(자동 생성 `frontend/bindings`는 제외).
- 맥에서 긴 한국어 문단이 든 파이썬 스크립트는 `python3 파일.py`가 "Non-UTF-8" 오류를 낼 수 있다 → `python3 -c "exec(open('파일', encoding='utf-8').read())"`로 실행.

## 릴리즈 절차 (맥, 사용자 승인 뒤에만)

1. 버전 올리기: `build/config.yml`, `build/windows/info.json`(4곳), `build/windows/wails.exe.manifest`, `build/darwin/Info.plist`·`Info.dev.plist`, `internal/sync/manager.go`(`AppVersion`), `server-data/version.json`(버전·노트), `agents.md` 버전 줄, `docs/current-work.md`·`docs/handover.md` 최신 릴리즈 줄.
2. `wails3 build GOOS=windows ARCH=amd64` → `bin/꼬미입시.exe` (이 맥은 Intel). `strings bin/꼬미입시.exe | grep 새버전`으로 버전 확인.
3. `bin/release-v<버전>/`(git 제외)에 `꼬미입시.exe`, 같은 파일 `kkomi-ipsi.exe`, Python `zipfile`로 만든 `kkomi-ipsi_v<버전>.zip`(안에 `꼬미입시.exe`, 이름 UTF-8 표시 0x800), `SHA256SUMS.txt`(exe 두 개·zip), `notes.md`.
4. 커밋 → `git tag v<버전>` → Gitea `origin`에 main·태그 푸시 → GitHub(`https://github.com/purnpado/kkomi_ipsi.git`)에 main·태그 푸시.
5. GitHub 릴리즈: `gh release create v<버전> --latest --notes-file notes.md` + 첨부 표시 이름 `kkomi-ipsi.exe (꼬미입시 실행 파일 · 처음 실행하면 꼬미입시.exe로 이름이 바뀜)`, `꼬미입시 v<버전> (zip, 안에 꼬미입시.exe) — 권장`, `파일 지문값(SHA-256)`.
6. Gitea 릴리즈: API `https://gitea.gguk.link/api/v1/repos/purnpadosori/PHGC-OFFLINE/releases`에 POST(tag_name·name·body) 뒤 `/releases/<id>/assets?name=...`로 `꼬미입시.exe`·zip·`SHA256SUMS.txt`를 multipart(`attachment`)로 올린다. 인증은 `git credential fill`(host gitea.gguk.link)의 사용자·비밀번호로 Basic 인증, **접속 정보는 출력하지 않는다**. 스크립트는 스크래치 폴더에 두므로 컴퓨터가 바뀌면 다시 만든다.
7. 확인: `https://github.com/purnpado/kkomi_ipsi/releases/latest/download/kkomi-ipsi.exe`를 받아 `SHA256SUMS.txt`와 지문값이 같은지 본다.
